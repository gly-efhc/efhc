# MIGRATION RULES

Статус: **NORM / ACTIVE**

## Действующие инварианты

- Alembic имеет один head.
- Единственная release migration:
  `backend/migrations/versions/0001_initial_release_schema.py`.
- Новая `0002+` без прямого решения пользователя запрещена.
- ORM/SSOT и физическая schema должны совпадать.
- Account owner — `users.global_id`; `users.user_id` отсутствует.
- Provider identity не используется как business owner.
- Raw SQL не может создавать скрытый второй канон таблиц или владельцев.

# EFHC Bot: правила миграционного слоя

## Цель

Миграции должны быть предсказуемыми, читаемыми и воспроизводимыми.
Проект EFHC Bot использует явные миграции без autogenerate.

## Текущий канон для первого релиза MVP

Сейчас проект находится в режиме первого запуска.
Для этого состояния активный миграционный слой жёстко зафиксирован как
одна главная миграция:

- `0001_init.py`

Для первого релиза MVP запрещено добавлять новые numbered migrations:

- `0002_*`
- `0003_*`
- и любые следующие номера

Пока не будет отдельного решения о переходе ко второй фазе релиза,
все изменения схемы должны вноситься в `0001_init.py` с сохранением
канона первого запуска.

## Что допускается позже

После отдельного решения по post-MVP фазе проект сможет перейти к
обычной последовательной линейке миграций:

- `0002_*`
- `0003_*`
- и далее

Но до этого момента такие миграции считаются нарушением текущего
релизного канона.

## Путь и формат имени файла

Миграции Alembic хранятся тут:

- `backend/migrations/versions/`

Когда проект перейдёт к post-MVP фазе, формат имени файла остаётся
таким:

- `NNNN_short_description.py`

Где:

- `NNNN` — последовательный номер с нулями слева
- `short_description` — короткое описание латиницей через
  подчёркивание

## Требования к содержимому

- Для текущего MVP `revision == "0001"`, а `down_revision == None`.
- Для post-MVP линейки `down_revision` указывает на предыдущий номер.
- Никаких `branch` и `depends` без явной причины.
- Любые деньги и балансы меняются только через сервисы.
  Миграции меняют схему, индексы и ограничения; seed допустим только
  там, где это прямо разрешено каноном.

## Ограничения стиля

- Каждая строка в файлах миграций не длиннее 72 символов.

## Порядок работы

1. Сначала проверить, остаётся ли проект в режиме `0001 only`.
2. Если да, менять только `0001_init.py`.
3. Если проект переведён в post-MVP фазу отдельным решением,
   разрешается открывать следующую numbered migration.
4. После изменений проверять compileall, tests и связанный docs layer.
