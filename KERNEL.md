# KERNEL.md — операционный контракт публичного репозитория EFHC

**Статус:** ACTIVE / PUBLIC-SAFE · **Область:** `gly-efhc/efhc` · **OWNER:** владелец EFHC.

Прочитать **один раз за операционный контекст**, после `AGENTS.md` и `START_HERE.md`. Это Markdown-диспетчер, **не** исполняемый Kernel, backend-модуль или копия приватного `efhc_archive/KERNEL.md`. Не запускать повторно на каждую итерацию.

## 1. Система источников

EFHC использует независимые контуры:

1. **Документальный:** приватный [`gly-efhc/efhc_archive`](https://github.com/gly-efhc/efhc_archive) и отдельно утверждённые OWNER физические ZIP. Здесь принадлежат решения, CANON, SSOT, NORM, архитектура, ТЗ, номерные REPORTS/CYCLES.
2. **Исходный код:** `gly-efhc/efhc`; фактический `CODE_HEAD` фиксирует, что находится в конкретном ref, но не доказывает состояние развернутого приложения.
3. **Исполнение:** CI, браузер, серверный backend, база данных, TON и артефакты релиза проверяются независимо. DEMO, Pages, локальный build и исторический PASS не доказывают финансовую проводку или production.

Никакой автоматической синхронизации между этими контурами не предполагать. Удалённый `ARCHIVE_HEAD` и локальный `Archive_vNNN.zip` имеют разные идентификаторы и сверяются содержательно. Нельзя заявлять полный remote/ZIP parity по совпадению нескольких файлов.

## 2. Маршрут чтения

`AGENTS.md → START_HERE.md → KERNEL.md (однократно) → INDEX.md → точный CODE_HEAD → предметный исходник/тесты`.

Если требуется приватная норма: только авторизованный GitHub-коннектор → приватные `AGENTS → START_HERE → KERNEL (однократно) → INDEX → 01_CANON/TERMS.md` → README раздела/вложенных каталогов → предметный CANON/`05_SSOT`/`06_NORM`. Применять лишь необходимые документы, не перечитывая тысячи отчётов. Публичные GitHub URL закрытого репозитория не дают доступа без полномочий. Не использовать публичный web/raw HTTP, прокси или браузер для обхода private доступа.

**Нормативный приоритет:** последнее прямое решение OWNER → `01_CANON/OWNER_DECISIONS.md` и тематический CANON → `05_SSOT/` → `06_NORM/` → утверждённые архитектура и ТЗ в `13_PLANS/TECHNICAL_TASKS/` → подтверждённый код как свидетельство реализации → `03_REPORTS/` и `04_CYCLES/` как история. Устаревшие номера и ссылки не воссоздавать из памяти.

Для работы с документами применять `06_NORM/DOCUMENTATION/DOCUMENT_MANAGEMENT_RULES.md`; для межрепозиторного перехода — `08_AI/AI_CROSS_REPO_ROUTING.md`; для нумерованных свидетельств — `06_NORM/DOCUMENTATION/REPORTS_CYCLES_FORMAT_CONTROL.md`.

## 3. Режимы и согласования

- `READ_ONLY`: чтение, анализ и сравнение, без записи, deploy и изменений состояния.
- `DOCS_WRITE_APPROVED`: изменение только прямо указанных публичных документов efhc.
- `CODE_WRITE_APPROVED`: изменение только названных исходников, тестов либо CI по разрешению OWNER.
- `RELEASE_DEPLOY_APPROVED`: самостоятельное распоряжение на публикацию после проверенного source/ref, тестов и артефактов.
- `PRIVATE_DOC_WRITE`: отдельное явное разрешение на запись в приватный Архив; не следует из права изменять efhc.

GitHub-доступ не является разрешением на действия. Не менять secret/ACL, backend, БД, финансовые остатки, TON, кошельки, CI или production без прямого соответствующего scope. При отсутствии обязательного контракта остановить только зависимую операцию, назвать конкретный `BLOCKED`/ `OWNER_HOLD`; не заменять источник догадкой.

## 4. Защита публичного контура

В public нельзя переносить приватные документы или их закрытое содержание, переписку OWNER, внутренние реестры, секреты, PII, исходные HTML-эталоны, отчетную историю или коммерческие детали. Разрешены публично безопасные ссылки, названия и минимальные правила инженерного исполнения. Не создавать публичный дубликат `CANON/SSOT/NORM`.

Публично присутствуют [`frontend/EFHC_APPLICATION_RULES.md`](frontend/EFHC_APPLICATION_RULES.md) (OWNER-утверждённый маршрут редакции B) и [`frontend/APPLICATION_RULES.md`](frontend/APPLICATION_RULES.md) (вторичная редакция). Их текст сверяется с текущим source и приватным `01_CANON/APP_RULES_OWNER_DECISION_B.md` и `05_SSOT/FRONTEND/APPLICATION_RULES.md`; они не становятся вторым независимым SSOT.

## 5. Технические инварианты

1. **UI:** сохранять прямо принятые механизмы темы, навигацию, Header/Bottom Nav, локализацию, FAQ, Wallet и защищённые части интерфейса. React Admin **не заморожен в целом**: его исправление по внешнему `FRONTEND_v866.html` допустимо при прямом scope и наличии эталона. Не заявлять визуальный parity без сравнения реально отрисованного интерфейса.
2. **Serwist/PWA:** действующий источник — приватный `05_SSOT/FRONTEND/EFHC_SERWIST_PWA_CACHE_STANDARD.md`; Serwist владеет PWA/CacheStorage. Не вводить независимые EFHC PWA-кеш-правила. Состояние Global ID/owner, сессий и безопасность финансовых запросов проверять по профильным контрактам отдельно.
3. **Backend/Identity/TON/finance:** фактическая проводка, идемпотентность, права Admin, привязка кошелька и on-chain settlement требуют проверок реального backend/ledger/TON; клики и mocks не доказывают завершение операции.
4. **Именование:** `NO_WORK_PREFIXES` действует для кода и программных идентификаторов, не для законных номеров циклов, Q-ID и отчетов. Не удалять сохранённые обязательства ради сокращения текста.
5. **QA:** не скрывать `FAIL` под `SKIP`, не отключать тесты и не переносить технический текст/диагностику в обычный пользовательский UI.

## 6. Исполнение, проверка и запись

1. `PIN`: зафиксировать точный HEAD, уполномоченный режим, список разрешённых файлов, контракты и возможные параллельные изменения.
2. `ROUTE`: через [INDEX.md](INDEX.md) и приватный предметный маршрут получить нужные требования и реальные исходники; не проводить повторный тотальный аудит.
3. `EDIT`: короткий адресный diff, без новых конкурирующих источников истины, скрытых массовых правок, force/reset и неразрешённого deploy.
4. `VERIFY`: только релевантные проверки; для frontend использовать скрипты [`frontend/package.json`](frontend/package.json) (`npm ci`, `npm run typecheck`, `npm run test:frontend-regression`, `npm run build`). Отдельно фиксировать `PASS/FAIL/PARTIAL/NOT_RUN`; документационная правка не требует фиктивного Next.js PASS.
5. `WRITE`: commit на разрешённой ветке, без перезаписи конкурирующих изменений.
6. `READBACK`: перечитать именно изменённые remote файлы; проверить SHA, доступные CI verdict и отсутствие закрытых материалов в public.
7. `HANDOFF`: `scope | mode | CODE_HEAD | ARCHIVE_HEAD/ZIP (если применимо) | changed paths | verification | protected unchanged | pending`.

Нумерованные CYCLES/REPORTS и Q&A относятся к приватному Архиву. Открыть новую итерацию, цикл, отчет или восстановить ранее исключённый Q-ID можно только в порядке, установленном OWNER. Ответы OWNER не пересказывать вместо дословного первоисточника.
